# Plan: per-model folders + C0/C6 on gpt-oss:20b (2026-10-06)

Issues: #12 (Task 1), #13 (Tasks 2–5). Spec: `docs/design/spec.md`. Conditions: `docs/conditions/README.md`. Runbook: `docs/runbook/README.md`. The reference implementation of Tasks 2–5 is the C6 plan `docs/design/plans/2026-10-05-c6-pilot-run.md` and its outputs in `results/comparisons/pilot_ollama-gemma4-31b_c6_vs_c0/`.

Goal: find out whether a smaller, less multilingual model shows the Bangla gap that gemma4:31b did not (gemma: c0 81.1% vs c6 82.2%, no detectable gap). Same tasks, conditions and settings; only the model changes, to `ollama-gpt-oss-20b` (model id `gpt-oss:20b`, Ollama Cloud free tier; the 2026-10-04 probe passed both chat and tool calling).

Scope (owner): **c0 vs c6 only** (c6 = BN task, BN system prompt, EN tool descriptions, replies forced to Bangla, i.e. the collaborators' setup). No c1 to c5 and no gemma repeats in this plan.

## Global Constraints

- **Free tier only.** Owner-approved budget: smoke10 about 80 requests, pilot about 684 requests (3.8 per task), so about 765 in total. Hard cap 4,000. **Stop immediately** on HTTP 402 or 429, a quota or credit message, or more than 3 consecutive 5xx errors. Report the error verbatim and never switch model or provider.
- From the project root, `source env.sh` in the same shell command as any uv call (the shell is zsh and the environment does not persist between calls). Python runs through `uv run --project WorkBench --frozen ...`. Install nothing globally and write nothing outside the project folder.
- Runs only through `scripts/run_condition.py`; it refuses to run on a dirty harness. Comparisons only through `scripts/compare_conditions.py`. HTML only through `scripts/build_report_html.py`.
- Existing runs and comparisons are read-only except where Task 1 moves them: gemma c0, c1 and c6, and every `results/comparisons/*gemma*` folder.
- Formats follow `docs/data/schema.md` v2. LLM requests per task = distinct `llm_input` per task (decision #32).
- **Git workflow (owner):** one GitHub issue per task. Work on a feature branch, open a PR whose body says `Closes #N`, then merge with `gh pr merge --merge --delete-branch`. Never commit on `main`. Commit trailer: `Co-Authored-By: Claude <model> <noreply@anthropic.com>`, naming the model that actually wrote the commit.
- Never print or commit secrets. Traces (`*_traces.json`) are git-ignored on purpose.
- Plain, direct English. Numbers in reports are copied from the generated CSVs. Claims stay cautious: n = 90, one run per side, single LLM annotator, unreviewed Bangla prompt.

## Task 1: Per-model folders (issue #12; branch `feat/per-model-folders`)

Target layout:
- Raw run: `WorkBench/data/results/<cond>[-<label>]/<subset>_<lang>/<model>/<model>_all_<ts>.csv`, plus `_meta.json` and `_traces.json`.
- Run log: `results/logs/<subset>/<model>/<cond>[-<label>]_<ts>.log`.
- `results/logs/run_log.csv` stays one file and gains no new columns; it already has `model` and `log_file`.
- Comparisons are unchanged: `results/comparisons/<subset>_<model>_<treat>_vs_<ref>/` is already per model.

Steps:
1. `WorkBench/src/evals/inference.py`: when `condition` is set, `save_dir` gains a final `<model_name>` path component. Without `condition`, behaviour stays upstream's. Update `tests/evals/test_conditions.py` (the layout assertions) and add a test that two models never share a folder.
2. `scripts/run_condition.py`: `results_dir` and `log_file` follow the target layout.
3. `scripts/compare_conditions.py`: `latest_results` looks in `<cond>[-<label>]/<subset>_<lang>/<model>/`. Update `tests/test_compare_conditions.py` if it builds paths.
4. Move the existing gemma raw runs with `git mv`, then move the ignored `_traces.json` files with plain `mv`:
   - `c0/pilot_en/`, `c0/smoke10_en/`, `c1/pilot_bn/`, `c1/smoke10_bn/` and `c6/pilot_bn/` each move into an `ollama-gemma4-31b/` subfolder.
   - The gemma logs (`results/logs/pilot/*_ollama-gemma4-31b_*.log`) move to `results/logs/pilot/ollama-gemma4-31b/` with the model part removed from the filename.
   - `results/logs/*/run_log_2026-10-04.txt` stay where they are.
   - Fix the `log_file` and `results_dir` paths in `results/logs/run_log.csv` so they point at the new locations.
5. Regenerate every gemma comparison. This is pure re-scoring with no API calls: pilot c1-vs-c0, smoke10 c1-vs-c0, pilot c6-vs-c0. Then rebuild both HTML reports.
   - Check: `git diff --exit-code` on every `metrics.csv` and `paired.csv` and on `results/summary.csv`. They must be byte-identical; only path fields in `run_meta_*.json` may change.
   - Known issue #9: for pre-flag runs, `harness_commit` is rewritten to the comparison-time commit. Restore the previous value so the diff stays limited to path fields.
6. Update the paths in `README.md` (folder map and output table), `docs/runbook/README.md`, `docs/conditions/README.md`, `docs/harness/repo_map.md` §8 and `progress.md` Current step. Do not edit dated decisions-log entries.
7. Run both test suites, `ruff check`, and `run_condition.py --dry_run` for gemma c0 (it must report "finished") and gpt-oss c0 (it must report "not started"). Commit, PR `Closes #12`, merge.

## Task 2: smoke10 gate on gpt-oss:20b (issue #13; branch `run/gpt-oss-20b`)

1. Dry run, then run c0, then c6, on `--subset smoke10 --model ollama-gpt-oss-20b`. For each, verify:
   - the run has 10 rows;
   - `_meta.json` has `condition`, `finished_at` and a clean commit;
   - the run's log has 0 lines with 402, 429 or 5xx;
   - requests (distinct `llm_input`) and the error count are recorded.
2. Run `compare_conditions.py --ref c0 --treat c6 --model ollama-gpt-oss-20b --subset smoke10`.
3. **Gate.** Proceed to Task 3 only if all three conditions hold:
   - (a) c0 completes ≥ 3/10;
   - (b) at least 8/10 c0 runs make one or more valid tool calls;
   - (c) no quota signal.
   If the gate fails, stop. Write the result to `progress.md`, commit, and ask the owner. The fallbacks per `progress.md` decision #34 are `ollama-gpt-oss-120b` or local `qwen3:8b`.
4. Commit the smoke runs, logs, comparison and `summary.csv`: `Smoke10 c0/c6 on gpt-oss:20b`.

## Task 3: full pilot runs on gpt-oss:20b

1. Run c0, then c6, on `--subset pilot --model ollama-gpt-oss-20b`, using a Bash timeout of 600000 ms per call. If a call times out, re-run the identical command; it resumes.
2. Verify the same items as in Task 2, with 90 rows. Commit: `Run c0 and c6 on the 90-task pilot (gpt-oss:20b)`.

## Task 4: comparison and failure analysis

1. Run `compare_conditions.py --ref c0 --treat c6 --model ollama-gpt-oss-20b --subset pilot`.
2. Produce `failure_labels.csv` and `failure_analysis.md` in `results/comparisons/pilot_ollama-gpt-oss-20b_c6_vs_c0/`.
   - Follow the exact method and format of the gemma c6 analysis: label every failed run in each discordant and both_wrong pair, scan all 90 c6 runs for language behaviour, compare the failure mix, draw cautious conclusions.
   - Add one section, "Compared with gemma4:31b". It is descriptive only: the c0 and c6 rates and the failure mix for both models, from the two `metrics.csv` files and the two `failure_labels.csv` files.
3. Commit: `Compare and analyse c6 vs c0 (pilot, gpt-oss:20b)`.
